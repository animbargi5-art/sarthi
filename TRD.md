## 2. Nebius Token Factory Integration Specification

### 2.1 Endpoint Architecture
Nebius Token Factory exposes high-performance, OpenAI-compliant endpoints optimized for NVIDIA GPUs. SĀRTHI communicates with Nebius asynchronously via HTTP/2 or WebSockets.

- **Base URL:** `https://api.tokenfactory.nebius.ai/v1` (or user-configured Nebius host)
- **Model Identifier:** `nvidia/nemotron-4-340b-instruct`
- **Authentication:** Bearer token authentication via `Authorization: Bearer ${NEBIUS_API_KEY}`

### 2.2 Request Parameters & Constraints
```json
{
  "model": "nvidia/nemotron-4-340b-instruct",
  "messages": [
    {
      "role": "system",
      "content": "You are the SĀRTHI Cognitive Physical AI Engine. Analyze robot telemetry anomalies and output structured recovery strategies adhering strictly to JSON schema."
    },
    {
      "role": "user",
      "content": "<Structured Telemetry Snapshot JSON>"
    }
  ],
  "temperature": 0.1,
  "max_tokens": 1024,
  "response_format": {
    "type": "json_object"
  }
}
```

### 2.3 Resiliency & Timeout Protocol
- **Client Timeout:** Enforced at $450\text{ ms}$. If no response is received within this window, the client aborts the request and falls back to a deterministic safe hold.
- **Retry Policy:** Maximum 1 immediate retry on HTTP 503/429; no exponential backoff during active robotic disturbances to prevent kinematic divergence.

## 3. NVIDIA Isaac Sim Integration Specification

### 3.1 USD Stage & Asset Setup
The simulation environment is defined as an Omniverse USD (Universal Scene Description) stage containing:
1. **Articulated Manipulator:** 7-DOF industrial robotic arm (e.g., Franka Emika Panda) with joint drive stiffness and damping configured for PhysX 5 compliance.
2. **End-Effector Rig:** Parallel-jaw or vacuum gripper equipped with:
   - High-rate 6-axis Force/Torque sensor primitive (`omni.isaac.sensor.ForceSensor`).
   - Contact reporting mesh for slip and normal force measurement.
3. **Sensor Array:**
   - Synthetic wrist-mounted RGB-D sensor producing aligned depth and point clouds.
   - Joint encoder stream publishing positions, velocities, and applied efforts at 100 Hz.
4. **Disturbance Generator Prim:** Python script extension within Isaac Sim capable of:
   - Applying instantaneous force/torque impulses to the grasped object or end-effector.
   - Dynamically altering surface friction coefficients ($\mu_s, \mu_k$) to induce micro-slips.
   - Spawning dynamic collision obstacles along the nominal trajectory.

### 3.2 Simulation Bridge Protocol
- **Telemetry Pipe (Outbound from Isaac Sim):** High-frequency streaming over a dedicated WebSocket connection carrying `TelemetrySnapshot` packets.
- **Actuation Pipe (Inbound to Isaac Sim):** Low-frequency trajectory setpoints and compliant impedance targets generated by SĀRTHI's safety-validated controller.

## 4. Backend Orchestration & Deterministic Safety Engine

### 4.1 Async Runtime Loop
The backend maintains an asynchronous event loop with two primary threads/tasks:
1. **Telemetry Ingestion & Ring Buffer Task:** Ingests incoming 100 Hz packets, updates a 300-sample sliding buffer, and computes real-time derivatives (acceleration, jerk, force deltas).
2. **Disturbance Detection & Deliberation Dispatcher:** Evaluates anomaly triggers every 10 ms. Upon anomaly confirmation:
   - Commands immediate local deceleration/hold.
   - Assembles the context payload.
   - Dispatches inference to Nebius Token Factory.
   - Hands off the response to the Safety Filter.

### 4.2 Deterministic Safety Guardrails
The safety layer acts as a strict firewall between the LLM output and the simulation bridge. A proposed plan is accepted **only if all the following conditions hold**:
$$\forall t \in [0, T], \quad q_{\min} \le q(t) \le q_{\max}$$
$$\forall t \in [0, T], \quad |\dot{q}(t)| \le \dot{q}_{\max}$$
$$\forall t \in [0, T], \quad p_{\text{EE}}(t) \in \mathcal{W}_{\text{safe}} = [x_{\min}, x_{\max}] \times [y_{\min}, y_{\max}] \times [z_{\min}, z_{\max}]$$
$$\text{Dist}(p_{\text{robot}}, \mathcal{O}_{\text{static}}) \ge d_{\text{clearance}}$$

If any constraint is violated, the candidate plan is rejected immediately, and the robot transitions to `SAFE_CONTROLLED_STOP`.
